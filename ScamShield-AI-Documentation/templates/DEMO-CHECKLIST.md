# ScamShield hackathon demonstration checklist

## Before stage

- [ ] Organizer rules/closing times checked
- [ ] Latest Git commit tagged; no secrets committed
- [ ] Working MVP built and independent operator can run it
- [ ] API and DB health green, Redis workers running
- [ ] Sandbox egress and SSRF tests pass
- [ ] Chrome extension loaded in separate profile (if selected)
- [ ] Tested benign and suspicious controlled fixtures
- [ ] Real discovery API key, quota and region checked
- [ ] Live / fixture banner clearly visible on all screenshots and case reports
- [ ] No actual usernames, card numbers, OTPs or private URLs in demo
- [ ] Report PDF matches case ID and evidence timestamps
- [ ] Second Chrome profile rule block and rollback tested
- [ ] Wi-Fi failure mode and local offline fixture rehearsed
- [ ] Two presenters know fallback sequence

## What to say precisely

- [ ] "Suspected" for automated findings, "analyst confirmed" only after review
- [ ] No invented accuracy or provider coverage figures
- [ ] Clear distinction between known pre-request blocks and unknown async checks
- [ ] Explain that Google Places `websiteUri` has billing and data-policy conditions
- [ ] No claims of official police deployment, recognition or evidence admissibility
- [ ] Mobile/AR/Rescue named as roadmap unless built

## Submission

- [ ] Submission artifact and link verified
- [ ] README and run instructions included
- [ ] Actual demo recorded (optional backup)
- [ ] Event deadline observed (Nov 25 2026 08:00 UAE)
- [ ] Proof of submission saved securely
